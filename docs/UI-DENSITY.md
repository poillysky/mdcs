# MDCS — 紧凑与协调排版指南

> 版本：v1.0  
> 日期：2026-08-21  
> 性质：**落地指导**（在契约内把页面做得更密、更齐，而不是另起一套风格）  
> 上位契约：[`UI-DESIGN-SYSTEM.md`](UI-DESIGN-SYSTEM.md)  
> 关联：[`UI-PLAYBOOK.md`](UI-PLAYBOOK.md) · [`UI-WIREFRAMES.md`](UI-WIREFRAMES.md) · [`UI-IOS.md`](UI-IOS.md)

**冲突裁决**：色值 / 圆角 / 阴影 / 红线仍以 DESIGN-SYSTEM 为准。本文只约束**密度、节奏、对齐与层级**；不得借「紧凑」引入拥挤、花哨装饰或第二套视觉。

---

## 0. 一句话目标

**紧凑** = 去掉无效空白，让一眼能扫完一屏关键信息。  
**协调** = 同一页里间距、字号、控件高度、对齐轴只有一套节奏。  

紧凑 ≠ 挤。挤是信息抢位；紧是空隙有用、节奏稳定。

---

## 1. 先判断：该紧还是该松

| 页面类型 | 默认密度 | 原因 |
|----------|----------|------|
| 设置 / 表单 / 配置 Tab | **偏紧** | 字段多，松了要狂滚 |
| 列表 / 表格 / 记录 | **偏紧** | 扫读效率优先 |
| 仪表盘首屏 / 空状态 | **偏松** | 首区要透气，避免一进门就闷 |
| 弹窗 / Drawer | **偏紧** | 高度有限，少套标题 |

同一页面内：**首区可略松，内容区偏紧**；禁止整页一会儿超松、一会儿超挤。

---

## 2. 密度刻度（在契约间距内选用）

契约间距仍是：`4 · 8 · 12 · 16 · 24 · 32 · 48 · 64`。  
紧凑页优先吃**左侧小档**，少用 48 / 64。

### 2.1 推荐对照

| 场景 | 舒适（偏松） | 紧凑（推荐配置/列表） | 禁止 |
|------|--------------|----------------------|------|
| 主区外边距 | 32 / 24 | 24 / 16 | 页面顶再叠大空白 |
| 页面标题下边距 | 24 | **16** | 标题下再空一块再放工具栏 |
| 区块与区块 | 32–48 | **24**（最多 28） | 每个 section 再套大卡片撑开 |
| 区块标题 → 内容 | 12–16 | **8–12** | 标题和控件之间再塞说明墙 |
| 表单行间距 | 16 | **12** | 行与行各加 margin 叠 gap |
| 卡片内边距 | 24 | **16**（复杂卡可 16/20） | 卡套卡再各垫 24 |
| 工具栏 gap | 12–16 | **8–12** | 按钮之间空隙大于按钮本身 |
| 表格行高 | 44–48 | **40–44** | 行高 > 52 却无多行内容 |

### 2.2 三层间距心智模型

改任何页面时只认三层，不要第四层「随手 margin」：

1. **页面壳**：主区 padding（与侧栏、安全区有关）
2. **区块**：section 之间的 gap
3. **组内**：标题→控件、行与行、控件内 padding

同一层只用**一个**间距值（或 gap），禁止 `margin + gap + padding` 三重叠加同一方向。

## 3. 协调：让页面「像一个人设计的」

### 3.1 一条对齐轴

- 表单标签列、输入起点、表格列起点，尽量落在同一竖线。
- 标签与控件：**左对齐标签 + 右控件**，或整行「标签上、控件下」二选一；**同页不得混用两种**。
- 工具栏主按钮组右对齐或标题同行右侧；次要筛选靠左，不要左右各撒一堆。

### 3.2 字号阶梯要短

一页里建议最多出现：

| 角色 | 字号 | 说明 |
|------|------|------|
| 页标题 | 28 → 可降到 **22–24**（设置子页） | 子页不要再刷 28 |
| 区块标题 | 13–15 或小号大写标签 | 设置里用 muted 小标题即可 |
| 正文 / 控件 | 14 | 固定 |
| 说明 | 12 | 一句够用 |

禁止：页标题 28 + 区块 18 + 卡片标题 15 + 行内再加粗 16 四套同时出现。

### 3.3 控件高度统一

| 控件 | 高度 |
|------|------|
| 输入 / 下拉 / 默认按钮 | **36px** |
| 小号按钮 / 表格内动作 | **32px** |
| 开关、Chip | 按现有组件，不另起高度 |

同一工具栏禁止 28 / 36 / 40 混排。

### 3.4 边框与表面要克制

协调的关键是**少一层容器**：

- 能用分割线分节，就不要每节一张厚卡片。
- 已在 `--surface` 面板内，子块默认透明底，只用 `border-top` 或 gap 分隔。
- 危险区才允许单独描边面板（如「自动清理」）。
- 全页禁止：卡片套卡片套卡片。

### 3.5 颜色节奏

- 中性灰承担结构；`--accent` 只出现在：主按钮、选中、必要链接。
- 一屏内主按钮 **≤ 1 个视觉焦点**（其余次按钮 / 文字按钮）。
- 说明文字一律 `--text-muted` / `--text-dim`，不要拿 accent 染说明句。

## 4. MDCS 页面配方（直接套）

### 4.1 设置类（整理 / 监控 / 元数据…）

```text
[页头] 标题一行 + 可选一句说明（说明 ≤ 1 行）
[区块] 小写大写标签标题（13px muted）
[内容] 下拉 / 开关 / 路径：行高紧凑，hint 跟在控件下或右侧弱化
[区块间距] 24px 左右
```

**要做：**

- 五选一、枚举类 → **下拉**，不要五张大卡占半屏。
- 开关行：左标签+hint，右开关；行距 12。
- 长说明折叠进 hint，默认不展开大段。

**不要做：**

- 「整理规则」大标题下再空 24，再来五个模式卡。
- 每个字段一套独立卡片。

### 4.2 列表 / 表格类

```text
[页头] 标题 + 右侧主操作
[工具栏] 筛选 / 搜索一行排完；gap 8–12
[表] 表头弱底；行高 40–44；操作列图标或文字按钮 sm
```

- 筛选不要换行成三行工具条；放不下再「更多筛选」。
- 空状态居中短文即可，不要巨大插画占位。

### 4.3 仪表盘

- 统计条：横向一排、单行数字，**不要**每人一张高卡片。
- 下方两列内容区 gap 用 16，不要 32 再套阴影卡。
- 首屏只保留：状态摘要 + 最近任务/失败入口；细节进子页。

### 4.4 弹窗

- 标题栏紧：上下 padding 12–16。
- 表单 `form-grid` gap 12。
- 底栏按钮右对齐，主次一对即可。

## 5. 改版检查清单（提交前过一遍）

### 紧凑

- [ ] 首屏是否仍有「只能看见标题和空白」的大洞？
- [ ] 区块间距是否基本落在 16/24，而不是 32/48 混飞？
- [ ] 枚举选项是否用了下拉/分段，而不是大卡矩阵？
- [ ] 说明文案是否压缩到 1 行 hint，而不是段落墙？
- [ ] 同一方向是否只有一种间距机制（优先 gap）？

### 协调

- [ ] 同页标题阶梯是否 ≤ 3 级？
- [ ] 输入/按钮高度是否统一 36（sm 32）？
- [ ] 标签列 / 控件列是否对齐？
- [ ] 是否避免卡套卡？危险区是否才单独描边？
- [ ] 主色是否只打在真正主操作上？

### 红线（仍不可破）

- [ ] 未引入渐变、发光、厚阴影、emoji 图标墙
- [ ] 未自创色值；仍用 DESIGN-SYSTEM Token
- [ ] 未为了紧凑把可点区域压到 < 32px 高（移动端尤甚）

## 6. 反例 → 正例

| 反例 | 正例 |
|------|------|
| 五种整理模式各一张说明卡 | 一个 `<select>` + 一行 hint |
| 页标题 28 + 再来 h2 18 + section 15 | 子页标题 22，section 用 13 muted 标签 |
| section 外边距 48，内部再 padding 24 | section gap 24，内部 padding 0 或 16 |
| 工具栏两行：一行搜索一行按钮 | 单行：左搜索，右按钮组 |
| 每条设置包在圆角阴影卡里 | 分割线或 gap 分组，仅危险组描边 |
| 表格行高 56，单元格垂直居中一大块空 | 行高 40–44，内容单行省略 |

## 7. 给 Cursor / AI 的执行口令

改 `apps/web` 布局密度时：

1. 先读本文 + `UI-DESIGN-SYSTEM.md`，**不新开视觉风格**。
2. 优先减：重复标题、大卡矩阵、叠 margin、无用说明段。
3. 优先统一：控件高度、区块 gap、字号阶梯、对齐轴。
4. 改完用 §5 清单自检；移动端再确认触控高度与安全区。

口令示例：

> 按 `docs/UI-DENSITY.md` 把本页改为紧凑协调密度：去掉大卡，统一 36 高控件与 24 区块间距，说明改为一行 hint。

## 8. 与契约原文的关系说明

DESIGN-SYSTEM 写「留白优先 / 宁松勿挤」，指的是：

- **不要信息过密到难扫、难点**；
- **不要为了装饰填满**。

本文是在该前提下的**工程密度指导**：配置与列表场景应主动收掉**无效留白**，用稳定节奏换信息效率。二者不冲突——  
**松在该松的首屏与空状态，紧在该紧的表单与表格。**
