## 1. 目标与设计准则

本手册只解决一个问题：**如何把已有功能做得“看着舒服、用着顺手、操作不费脑”**。

### 1.1 三个体验目标

1. **好看**：信息层级清晰，视觉节奏稳定，暗色主题不刺眼。
2. **自然**：用户每一步都知道“现在在哪、能做什么、做完会怎样”。
3. **高效**：大部分高频动作（扫描、建任务、看结果、改配置）3 步内完成。

### 1.2 设计原则（必须执行）

- **先状态后操作**：先给用户看状态，再提供动作按钮。
- **就近反馈**：哪里触发，反馈就出现在哪里（按钮旁、行内、弹窗内）。
- **低风险默认**：默认使用安全选项（如 `dry-run`、不覆盖、不删除源）。
- **一致性优先**：同类控件、同类文案、同类反馈统一样式和语义。
- **渐进暴露**：默认展示核心选项，高级能力折叠到“高级设置”。

### 2. 视觉系统（好看）

> **权威来源**：[`UI-DESIGN-SYSTEM.md`](UI-DESIGN-SYSTEM.md)。下文仅保留体验骨架；具体色值、字号、阴影、禁止项以 DESIGN-SYSTEM 为准（浅色极简克制，禁止霓虹/厚阴影/网红风）。

#### 2.1 页面骨架

- 左侧固定导航（功能入口稳定，不跳位）。
- 右侧主内容采用三层结构：`页面标题区` → `工具栏区` → `内容区`。
- 内容区统一 12 栏栅格，卡片间距固定（建议 16 或 20）。

### 2.2 信息层级

- **H1 页面标题**：只说页面目标，如“手动任务”“数据源”“刮削记录”。
- **H2 区块标题**：只说区块职责，如“全局设置”“字段优先级”。
- **正文文案**：一句话说明“作用 + 风险/副作用”。
- **辅助说明**：灰色小字，不超过两行。

### 2.3 颜色与对比

- 主色用于“主行动作”（创建、保存、执行）。
- 成功/警告/错误必须固定颜色，不随主题变化语义。
- Tag 与 Badge 用“低饱和底色 + 高对比文字”。
- 暗色背景下正文对比至少达到可读标准（避免灰上灰）。

### 2.4 卡片与表格美感

- 卡片：统一圆角、统一阴影、统一内边距。
- 表格：表头固定、行高一致、悬停高亮、状态列视觉最突出。
- 数字字段（线程、成功数、失败数）右对齐，提升扫描效率。
- 长文本统一省略号 + 悬浮完整内容。

### 2.5 空状态与骨架屏

- 空状态必须包含：当前状态 + 下一步建议 + 主按钮。
- 加载态优先用骨架屏，不用大面积转圈。
- 首屏慢查询超过 400ms 才显示加载占位，减少闪烁感。

## 3. 交互模型（自然）

### 3.1 交互基础规则

- 所有按钮必须有三态：默认 / hover / disabled。
- 危险操作必须二次确认：取消任务、删除记录、覆盖文件。
- 弹窗关闭行为一致：右上角关闭、Esc、点击蒙层（危险操作除外）。
- 表单未保存离开时必须提示“你有未保存修改”。

### 3.2 反馈分层

- **行内反馈**：字段校验失败、输入格式错误。
- **区块反馈**：某个 Tab 保存成功/失败。
- **全局反馈**：任务创建成功、系统连接失败（Toast）。
- **持续反馈**：长任务进度（进度条 + 分阶段状态）。

### 3.3 延迟与动效

- 按钮点击后 100ms 内给视觉响应（loading 或 pressed）。
- 页面切换动效 120–180ms，避免“飞来飞去”。
- 弹窗/抽屉动效方向固定（弹窗淡入，抽屉侧滑）。
- 禁止多重并行动画干扰任务信息阅读。

### 3.4 输入体验

- 目录选择类字段必须支持：手输 + 文件夹选择器。
- 多值字段（Tag）支持回车添加、退格删除。
- 模板输入（命名、Webhook Body）支持语法提示与一键插入变量。
- 数字输入强约束（最小值、最大值、步进）防止脏配置。

## 4. 操作流设计（高效）

### 4.1 四条高频路径

1. **扫描并创建任务**：文件管理 → 选择路径 → 创建任务。
2. **快速修配置**：设置页改动 → 保存 → 回任务页重试。
3. **排查失败记录**：刮削记录 → 详情日志 → 定位字段来源。
4. **调优数据源**：数据源页改优先级 → 测试 → 回看结果。

### 4.2 “3 步完成”要求

- 建任务：选路径 → 选模式 → 创建（高级设置可选）。
- 重试失败：筛选失败 → 批量勾选 → 重试。
- 改字段优先级：选分类 → 调顺序 → 保存。

### 4.3 页面级操作策略

#### 主界面（Dashboard）

- 顶部四卡只放关键数字，不放复杂控件。
- 最近活动支持点击跳转到记录详情。
- 异常数字（失败激增）高亮并提供“查看失败”快捷入口。

#### 手动任务

- 列表以“状态 + 进度”优先展示。
- 创建弹窗默认简版，`高级设置` 单独入口。
- 高级设置内显示“当前继承自全局/当前已覆盖”标识。

#### 刮削记录

- 列表支持多条件组合筛选（状态 + Kind + 时间）。
- 详情页左右分栏固定：左数据、右日志，避免上下跳读。
- 字段来源 Tag 点击可高亮对应日志节点。

#### 文件管理

- 扫描模式用于“临时入口”，文件树模式用于“常驻浏览”。
- 选中计数与主操作按钮始终可见（顶部吸附）。
- 大目录分页和虚拟滚动必须启用，避免卡顿。

#### 数据源

- Provider 卡片强调“可用性状态”（在线/离线/超时）。
- 优先级编辑采用拖拽 + 键盘可操作双模式。
- 字段优先级页提供“恢复默认”与“复制到其他分类”。

#### 设置（11 Tab）

- 每个 Tab 顶部放“本页说明 + 风险提示 + 保存按钮”。
- 保存后保留滚动位置，不强制回到顶部。
- 命名、水印、Webhook 页面必须有即时预览/测试入口。

## 5. 微文案规范（不别扭）

### 5.1 文案语气

- 使用“动作 + 结果”表达：如“保存修改”“创建任务”“测试连接”。
- 避免技术黑话堆叠；必须出现术语时加一行白话说明。
- 错误提示给出“原因 + 建议动作”，不只说失败。

### 5.2 常用文案模板

- 成功：`保存成功，配置已生效。`
- 失败：`保存失败：{原因}。请检查 {建议项} 后重试。`
- 风险确认：`此操作可能覆盖现有文件，确认继续？`
- 空状态：`当前暂无数据。你可以先 {推荐动作}。`

### 5.3 状态命名统一

- 任务：`待处理 / 进行中 / 已完成 / 失败 / 已取消`
- 网络：`可用 / 受限 / 超时 / 未配置`
- 配置：`继承全局 / 已覆盖 / 未保存`

## 6. 可用性与无障碍

### 6.1 键盘与焦点

- 所有核心操作支持键盘触达（Tab 顺序正确）。
- 弹窗打开后焦点落到第一个可编辑字段。
- Esc 行为一致；关闭后焦点返回触发按钮。

### 6.2 表格可读性

- 支持列宽拖拽（可选）和最小宽度保护。
- 状态列固定宽度，避免因文案长度导致跳动。
- 支持按时间、状态、编号排序。

### 6.3 错误恢复

- 网络抖动时允许“重试上一次操作”。
- 提供“复制错误详情”便于排查。
- 长任务失败保留上下文，不清空用户输入。

---

## 7. 性能体验要求

- 首屏可交互时间尽量控制在 2 秒内（本地部署环境）。
- 列表首批加载优先返回核心字段，详情懒加载。
- 所有分页接口返回总数、当前页、下一页可用性。
- 高频轮询页面避免全量刷新，采用增量更新。

## 8. 实施建议（落地顺序）

### P1（先把“自然”做出来）

1. 统一页面骨架与工具栏结构（所有主页面）
2. 统一按钮/Tag/Toast 状态体系
3. 手动任务创建流程改成“简版 + 高级设置”
4. 列表页统一筛选条和分页交互

### P2（再把“好看 + 高效”做出来）

1. Dashboard 指标卡视觉重构
2. 刮削记录详情双栏与日志高亮联动
3. 数据源优先级拖拽体验完善
4. 命名/水印/Webhook 预览与测试体验

### P3（最后做“专业感”）

1. 动效与过渡节奏统一
2. 空状态与骨架屏精细化
3. 错误恢复与可观测性体验完善

## 9. 验收清单（UI/UX）

每个新页面上线前，至少通过以下检查：

- 看起来是否与其他页面同一套视觉系统（间距、色彩、圆角、字体）？
- 关键任务是否 3 步内可达？
- 危险操作是否都有确认与可撤销策略？
- 错误信息是否可理解、可恢复？
- 低网速/失败场景是否有明确反馈？
- 键盘能否完成核心流程？
